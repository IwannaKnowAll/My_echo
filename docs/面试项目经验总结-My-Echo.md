# 【My Echo 本地备忘录 App — 面试项目经验总结】

> 用途：面试项目经验陈述稿。项目版本「0.2.0」，交付平台 macOS。

## 1. 一句话项目概述

My Echo 是一款 Mac 本机单用户备忘录桌面应用，采用 Tauri 2 + Vue3 + TypeScript + SQLite 纯本地架构（无网络、无账号、无云端），由「1 个主协调 Agent + 5 个角色子 Agent」的多智能体流水线协作开发完成，我负责整体产品设计、Agent 协作体系搭建与集成验证。

## 2. 产品基础介绍

- **产品定位**
  面向个人日常记录的 Mac 桌面备忘录，核心卖点是「隐私优先」：数据全部落在本机 SQLite，应用不发起任何网络请求，无登录、无云同步。

- **目标用户**
  单机单用户，重视数据私密性、追求快速记录的个人用户。

- **功能版图（按优先级分期交付）**
  - P0（v0.1.0 已交付）：备忘录增删改查；标题+正文模糊搜索；列表按更新时间倒序。
  - P1（v0.2.0「轻量强化包」已交付）：标签系统（多标签、按标签筛选、可与关键词搜索叠加）；待办勾选（正文 `- [ ]` 语法渲染为复选框，列表显示完成进度）；全局速记（菜单栏常驻 + 全局快捷键唤起，回车即存）；本地提醒（到点 macOS 本地通知，不联网）；主题三态（浅色/深色/跟随系统，持久化）；键盘快捷键体系（支持自定义改键）。
  - 规划中：置顶与归档、回收站软删、本地加密与备份导出。

- **核心用户路径**
  「想起来 → 记下来 → 找得到 → 被提醒」：全局快捷键速记降低记录门槛，搜索+标签保证检索，本地提醒让记录闭环。

## 3. 技术栈

- **前端**
  Vue3 Composition API + TypeScript（禁用 any），Vite 构建，Vitest + jsdom + @vue/test-utils 做组件与逻辑测试，vue-tsc 做类型门禁。

- **壳层**
  Tauri 2 + Rust。前端通过 Tauri Command（invoke IPC）调用壳层能力，无 HTTP 后端。

- **存储**
  SQLite（rusqlite，bundled 编译），备忘录、标签、备忘录-标签关系三张表，时间字段统一 ISO8601 文本存储。

- **系统能力**
  托盘图标（tray-icon）、全局快捷键（tauri-plugin-global-shortcut）、macOS 本地通知、应用配置持久化。

- **选型理由**
  对比 Electron，Tauri 用系统 WebView + Rust 壳，安装包与内存占用小一个量级，且 Rust 侧类型安全契合「纯本地、高可靠」的产品诉求；SQLite 嵌入式零运维，契合无后端约束。

## 4. 产品设计亮点

- **隐私优先的架构级承诺**
  不是功能开关而是架构约束：无 HTTP 服务、无网络请求写进硬约束，从根上消除数据外泄面。

- **轻量语法复用**
  待办不引入富文本编辑器，直接复用 Markdown 风格的 `- [ ]` / `- [x]` 行语法，纯文本存储、渲染层解析，实现成本与数据可迁移性双赢。

- **设计令牌体系**
  UI 规范全部落成 CSS 变量级设计令牌（色板、字号、间距、圆角），深色模式只需扩展一套深色调色板即可全量生效，主题三态零硬编码切换。

- **搜索与筛选可叠加**
  关键词 LIKE 模糊搜索与标签筛选正交设计，可任意叠加；搜索大小写不敏感，排序固定按更新时间倒序，行为可预期。

- **桌面端效率细节**
  全局速记把「想起 → 记下」压缩到一次快捷键；高频操作全量绑定快捷键且支持设置页自定义改键（组合须含修饰键、同上下文查重）；提醒、主题、键位均持久化于本机应用配置，重启不丢。

## 5. Agent 协作设计思路（核心亮点）

- **角色分工：五子 Agent + 主协调**
  - Planner：需求分析与架构规划，产出建表 SQL、Tauri Command 契约、原子任务清单；沙箱 read-only，只出文档不写码。
  - UI_Designer：页面结构、交互流程、CSS 变量级设计令牌；同样 read-only。
  - Frontend：只改 client/，按契约与设计令牌实现界面。
  - Shell：只改 src-tauri/，实现 Command、SQLite 存取、打包签名与发布清单。
  - Reviewer：质量把关，只可写测试文件，禁止改业务代码，发现问题出审查报告而非直接动手。
  - 主 Agent（我）：流程协调、集成验证、配置修复，不直接写归属子 Agent 的业务代码。

- **单一事实源**
  需求细节唯一存放于根目录 AGENTS.md，各角色 toml 只定义职责与边界、禁止重复定义需求；需求变更只改 AGENTS.md，再沿「Planner 重出契约 → 设计更新 → 开发执行 → 审查对齐」链路传导，从机制上杜绝多源需求漂移。

- **契约优先**
  Planner 先出 SQLite 建表 SQL 与 Command 契约（命令名、入参类型、返回 JSON 示例、异常返回约定），前后端才并行开工；Reviewer 以契约为基准做一致性审查，契约成为前后端唯一的对接语言。

- **目录边界 + 沙箱隔离**
  Frontend 只碰 client/、Shell 只碰 src-tauri/、规划类角色直接 read-only 沙箱；越界即流程违规。物理隔离让并行开发零冲突，也让问题定位天然二分（前端现象还是壳层现象）。

- **质量门禁与自动修复循环**
  Planner → UI_Designer → Frontend+Shell 并行 → Reviewer 审查 → 有 P1/P2 问题则对应子 Agent 修复（须注明修改文件清单）→ Reviewer 增量复审 → 循环直到「P1 清零、P2 ≤ 2」或达上限 → 主 Agent 集成验证（启动、SQLite 读写、核心流程、打包、环境兼容）→ Shell 打包发布、Reviewer 查验发布清单。

- **防死循环与人工介入设计**
  P1 阻塞必修；P2 同模块循环上限「3」次后自动降级为建议项；P3 记录待办不阻塞；同一问题「3」次未解决或跨模块架构问题，升级人工决策。流程有出口，不会无限空转。

## 6. Agent 应用开发的常见问题与解决方案

以下为项目中真实踩坑并沉淀的解法：

- **问题一：生成代码把中文写成 Unicode 转义序列**
  现象：子 Agent 产出的 .vue/.ts 文件中中文变成 `\u8bf7` 这类 `\uXXXX` 转义，界面可读性与可维护性崩坏。
  解法：在编码规范中明确「中文必须以实际 UTF-8 字符落盘、文件无 BOM」；Reviewer 增加 Unicode 转义专项检查，发现即记 P1 阻塞级，强制修复后复审。规范 + 门禁双保险。

- **问题二：需求多源导致 Agent 产物互相矛盾**
  现象：需求细节散落在多个文档/角色配置里，变更时漏改，下游产物打架。
  解法：单一事实源（AGENTS.md）+ 变更约定流程；角色配置文件只写职责边界，冲突时一律以 AGENTS.md 为准，Reviewer 把「违反 AGENTS.md」列为 P1。

- **问题三：Agent 越界修改，责任无法追溯**
  现象：规划角色顺手改代码、审查角色顺手修业务，既当裁判又当球员。
  解法：目录边界 + 沙箱模式（read-only / workspace-write）+ 角色 toml 明文职责；修复必须附修改文件清单，支撑增量复审。

- **问题四：前后端契约漂移**
  现象：前端调用与壳层实现的字段、类型、异常约定不一致，集成时才爆炸。
  解法：契约优先，契约精确到字段级 JSON 示例与异常返回约定；Reviewer 做契约一致性审查；不一致走修复循环而非口头对齐。

- **问题五：框架参数传递的隐性坑**
  现象：Tauri 2 的 Command 入参需以 `{ input }` 包裹对象传参才能正确反序列化，平铺传参直接失败。
  解法：踩坑结论沉淀进项目记忆（project memory），后续会话自动继承，避免重复踩坑。

- **问题六：校验口径前后端不一致**
  现象：标题长度限制前端按 UTF-16 码元计数、后端按 Unicode 标量计数，emoji 等增补字符下口径差「1」。
  解法：契约必须把校验规则定义到字符编码口径级别；此类问题记入待办清单限期收敛。

- **问题七：开发态与发布态行为不一致**
  现象：直接运行 debug 可执行文件出现白屏——debug 版依赖前端 dev server，dev server 未启动即白屏；用户误以为是应用故障。
  解法：集成验证清单纳入「启动方式核验」，明确开发用 tauri dev、交付用 release 包；发布清单标注产物路径与版本。

- **问题八：修复循环失控风险**
  现象：审查-修复往返可能无限循环，消耗预算却无收敛。
  解法：分级门禁（P1 必修 / P2 限次降级 / P3 挂起）+ 循环上限 + 人工介入触发条件，给流程装「熔断器」。

- **通用建议（未踩坑但值得预设）**
  - 契约要包含异常路径：只约定成功返回的契约，集成期必出异常处理分歧。
  - 集成验证由主协调角色执行而非子 Agent：子 Agent 视角局限在自己的目录边界内。
  - 给 Agent 配项目级记忆：把框架坑、口径约定沉淀为持久记忆，跨会话复用。
  - 测试归属要独立：写测试的角色不能同时改业务代码，否则测试失去第三方属性。
